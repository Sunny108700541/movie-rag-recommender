# Movie RAG Recommender

A semantic movie recommendation engine built in Node.js using local sentence embeddings and cosine similarity search — no external API keys required.

## Overview

This project implements the retrieval half of a Retrieval-Augmented Generation (RAG) pipeline: movie descriptions are converted into vector embeddings using a locally-run transformer model, and recommendations are generated by comparing vector similarity rather than keyword matching. This allows the system to understand *meaning* — a search for "space survival adventure" can surface movies like *The Martian* or *Gravity* even if those exact words never appear in the description.

## How it works

```
movies.json (raw data)
      │
      ▼
Embed each movie description  ──►  vector (384 dimensions)
      │
      ▼
Store movies + embeddings in memory
      │
      ▼
User submits a query / selects a movie
      │
      ▼
Embed the query in the same vector space
      │
      ▼
Compute cosine similarity against every movie vector
      │
      ▼
Sort by similarity, return top-K matches
```

## Features

- **Free-text semantic search** — describe what you want to watch, get ranked matches
- **"Similar movies" lookup** — find movies close in meaning to a given title
- **Fully local embeddings** — no OpenAI/Cohere API key, no per-call cost, runs offline after first model download
- **Functional, layered architecture** — data models, embedding engine, service logic, and controller are cleanly separated

## Tech Stack

| Layer | Tech |
|---|---|
| Runtime | Node.js |
| Embeddings | [Transformers.js](https://github.com/xenova/transformers.js) (Hugging Face) |
| Model | `Xenova/all-MiniLM-L6-v2` (384-dim sentence embeddings) |
| Similarity | Cosine similarity (custom implementation) |
| Style | Functional programming (factory functions, pure functions, no classes) |

## Project Structure

```
movie-rag/
├── data/
│   └── movies.json          # movie dataset (title + description)
├── model/
│   └── movie.js
    ├── embeddingModel.js           # factory functions for data shapes       
├── movieService.js            # core logic: load, search, similarMovies, cosine similarity
├── movieController.js         # thin interface layer over movieService
├── demoApplication.js         # wires embeddingModel + movieService + controller together
└── index.js                   # entry point — runs sample search + similar-movies queries
```

## Setup

```bash
git clone <your-repo-url>
```

## Usage

```bash
node index.js
```

On first run, the embedding model (~90MB) downloads and caches locally. Subsequent runs use the cached model with no network calls.

## Design notes

- **Why separate `MovieData` / `Movie` / `MovieMatch` shapes?** They represent different stages of the same entity: raw data (no embedding), enriched data (with embedding, used internally for search), and output data (score only, never leaking the raw embedding vector to a consumer).
- **Why functional over class-based?** State (like the loaded model or the in-memory movie list) is passed explicitly as function parameters instead of being hidden on `this`. This keeps every function pure and independently testable.
- **Why cosine similarity?** It measures the angle between two vectors rather than their magnitude, making it well-suited to comparing sentence embeddings regardless of text length.
